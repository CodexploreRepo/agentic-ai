## What you will be able to do

- Run a real error analysis: read twenty failures, group them, count the groups, fix the biggest
- Build component evals for retrieval, tool selection and synthesis separately
- Write an LLM judge that is hard to flatter, and validate it against your own labels
- Optimise cost and latency without guessing which step is expensive

## Build

**Lab 04 — Error analysis on a deliberately broken agent**

You are handed an agent that passes 58% of its eval set and a hundred traces. Find the cause. It is one component, and the aggregate score does not tell you which — the failure taxonomy you build does.

## Takeaways this module is built around

1. The aggregate score tells you there is a problem; only the taxonomy tells you what to fix
2. A judge weaker than the system it grades produces numbers you cannot act on
3. Cost per *successful* task is the only cost metric worth tracking
