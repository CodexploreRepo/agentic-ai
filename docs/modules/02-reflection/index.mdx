Make a system critique and improve its own output — then check whether the second draft is actually better.

## What you will be able to do

- Build a generator/critic loop where the critic has real leverage, not just a different prompt
- Wire an external signal (a linter, a failing test, a SQL error) in as the critic
- Decide when to stop revising, instead of running a fixed number of rounds
- Measure whether reflection earned its 2-3x cost on your eval set

## Build

**Lab 02 — A SQL analyst that fixes its own queries**

Generate SQL against a channel-analytics schema, run it, and feed the database's own error messages back as the critic. The database is a perfect critic: it is never agreeable.

## Takeaways this module is built around

1. Self-critique with no new information mostly produces agreeable noise
2. An external signal beats a self-assessment every time it is available
3. Fixed-round loops spend money making drafts different rather than better
