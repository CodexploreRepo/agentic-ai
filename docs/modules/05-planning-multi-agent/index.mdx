Decide when more structure helps, and when it just adds latency.

## What you will be able to do

- Build an explicit planner and compare it against the implicit planning the agent loop already does
- Choose a replanning trigger that is not 'every step'
- Build a router, and notice how often it replaces an agent entirely
- Build a supervisor-and-workers team, and measure whether it beat one agent

## Build

**Lab 05 — One agent versus a team, on the same eval set**

Build a tech-news digest three ways: one agent with all the tools, a router plus specialists, and a supervisor with a researcher and a writer. Same eval set, same cases. Compare pass rate, cost and p50 latency.

## Takeaways this module is built around

1. Communication pattern is the design decision; agent count is not
2. Agents built on one model fail in correlated ways — they agree confidently and wrongly
3. Routing is often the honest answer to a request for 'an agent'
