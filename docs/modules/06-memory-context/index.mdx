Keep an agent coherent past its context window, without filling the window with noise.

## What you will be able to do

- Distinguish the four things called memory, and pick the right one for a requirement
- Budget a context window across instructions, tools, retrieval and history
- Compact a long conversation and detect when compaction dropped something load-bearing
- Decide a write policy: what is actually worth remembering across runs
- Exploit prompt caching by designing stable prefixes

## Build

**Lab 06 — An agent that survives a hundred turns**

Take a support agent through a conversation far longer than its context window. Add summarisation, then retrieval over the transcript, then durable user facts — measuring at each step whether the agent still answers correctly about turn 3.

## Takeaways this module is built around

1. 'Add memory' is not a task until you say which of the four you mean
2. Tool output is the main uncontrolled consumer of a context window
3. A poisoned memory persists across runs, which makes memory an attack surface
