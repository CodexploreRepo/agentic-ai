Connect agents to real systems over a standard protocol, and understand the trust boundary you just created.

## What you will be able to do

- Explain what MCP solves and what it does not
- Write an MCP server, and judge when an in-process tool is the better choice
- Consume third-party servers while treating them as third-party code holding your credentials
- Recognise tool poisoning and tool shadowing
- Place Agent Skills alongside MCP without confusing the two

## Build

**Lab 07 — Build and consume an MCP server**

Expose the channel-analytics database as an MCP server, consume it from the Module 01 agent, then attack your own setup with a poisoned tool description and watch what the agent does.

## Takeaways this module is built around

1. MCP turns N agents times M integrations into N plus M
2. A third-party MCP server is third-party code running with your credentials
3. Skills package know-how; MCP connects to systems. Different problems
